## Runtime flow
1. The KuroGames SDK calls the existing `kurogames-online` API for configuration and room operations.
2. Signed-in players use their Supabase access token. Guests receive a Cloudflare-signed, game-scoped multiplayer token valid for up to six hours from `POST /guest-token`; the guest ID is generated by the Worker and is not an Auth user.
3. The Edge Function validates guest credentials against the Worker and accepts them only for multiplayer room actions. Guest credentials cannot submit rankings, use cloud saves, read KURO profiles, or change game settings.
4. The Worker validates the account or guest credential and checks actual room membership via the existing `room_poll` action.
5. The Worker signs a 60-second connection ticket and forwards the authenticated WebSocket to the room's Durable Object.
5. The DO derives player identity from trusted Worker headers, never from client-supplied player IDs. It manages connection presence and broadcasts game events.
6. Room state get/update remain on the existing authenticated API for backwards-compatible persistence and optimistic concurrency. The DO carries real-time notifications/events.

## Guest multiplayer
- Guests do not receive a Supabase Auth user. The browser stores a short-lived signed token locally for the current game; the Worker creates the guest UUID and signs the credential.
- Guest identity is accepted only by the multiplayer room actions. The database room tables allow these signed ephemeral IDs, while account-bound tables such as scores and cloud saves retain their Auth foreign keys.
- The guest token expires after six hours. A new guest ID is issued after expiry.
- This bridge is for games using the KuroGames ONLINE SDK. Games that connect directly to Supabase Realtime using a Supabase Auth JWT need a separate transport migration before they can use Cloudflare guest credentials.

## SDK behavior
- `game-studio/kurog-online.js` uses this Worker endpoint by default for multiplayer.
- `window.KuroGamesDurableEndpoint = ""` can temporarily disable DO and use the legacy polling transport.
- Transient ticket/transport failures fall back to the legacy polling implementation. Authentication, missing room membership, and full-room responses fail closed rather than bypassing the checks.
- Existing API shape remains `KuroGames.multiplayer.createRoom/joinRoom`, `room.getPlayers()`, `room.onPlayersChange()`, `room.onMessage()`, `room.send()`, `room.getState()`, `room.updateState()`, and `room.leave()`.

## Remaining migration boundary
This stage moves multiplayer WebSocket/presence/event delivery to Cloudflare Durable Objects. Account authentication, game configuration, room create/join authorization, rankings, cloud saves, and state writes remain on the current authenticated Supabase Edge Function API. Those are separate migrations and must not be described as fully moved to Durable Objects yet.

## Deployment workflow
The manual GitHub Actions deploy workflow is gated by repository variable `DEPLOY_DURABLE_OBJECTS=true` and expects `CF_API_TOKEN` and `CF_ACCOUNT_ID` repository secrets. The Worker and secret have already been deployed directly through the connected Cloudflare account.
